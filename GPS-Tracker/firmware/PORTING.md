# Перенос ядра на устройство
tracker.cpp — компилируемое ядро выбора канала и очереди. Это не готовый HEX для платы.
Вызов step выполняет один цикл: новое валидное измерение GNSS, выбор транспорта и обработку подтверждения сервера.
Стабильный id головной точки используется при повторной отправке; сервер должен дедуплицировать (device_id, session_id, id).

Для nRF52840 требуется адаптер Nordic SDK/Zephyr: UART модема, AT-команды регистрации/APN/TLS, GNSS-парсер, BLE GATT, защищённое сопряжение, watchdog и управление питанием. Вместо глобальной очереди в RAM нужен журнал flash с восстановлением после отключения питания. session_id нужно сохранять или менять после каждого сброса.
BLE ACK принимается только после сохранения точки сервером, а не после доставки телефону. Телефонное приложение должно передавать пакет HTTPS и возвращать ACK с id. Разделять LTE retry и GNSS sampling; отправлять backlog без генерации новых точек. Нужны таймауты, backoff, CRC и проверка соответствия ACK текущему id.

В симуляции ack — подтверждение текущей точки, задаваемое испытателем; сетевые и радиодрайверы не исполняются. Очередь ограничена 256 точками, при переполнении новые точки отклоняются, lost растёт. GNSS отсутствует — новая точка не создаётся, накопленные точки можно отправлять.
